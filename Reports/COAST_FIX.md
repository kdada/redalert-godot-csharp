# 海岸拼接修复

本次针对“海岸边缘的地图拼接似乎不太对”的反馈，修正完整模板选择与海滩内侧的材质过渡。模拟地形、海陆边界、通行性和网络规则均保持原样。

## 原因

上一版从42种岸线中截取2×2窗口，以各格水面占比接近模拟水陆格为主要选择依据。这样虽然保留了块内原像素，却把弯岸截段当成直岸，甚至在部分陆地位置放入大模板的水块；没有检查重复块之间和四个转角的连接。此前美术完整性校验主要检查资源存在及像素转换，不能发现这些接缝错误。

独立核对219个原始TMP子块后，确认原始行列顺序、等角坐标转换和绘制偏移本身正确；所有岸线块均无高度、斜坡或额外图层，不需要修改投影。

另一处硬边来自内侧材质：原岸线干侧为green沙地，而非clear草地。其索引分布与green的相似度为0.799，与clear仅0.187。

## 修改

[地表生成器](../Tools/derive_terrain_layout.py) 现在使用完整原版2×2模板，并联合选择直岸、重复接缝和四角。当前96×96地图的方向对应如下；坐标方向沿模拟网格，x+为右下、y+为左下。

| 位置 | 水侧 | 完整模板 |
| --- | --- | --- |
| 北侧 | y- | shore19 |
| 南侧 | y+ | shore03 |
| 西侧 | x- | shore25 |
| 东侧 | x+ | shore09 |
| 西北角 | x-、y- | shore24 |
| 东北角 | x+、y- | shore15 |
| 西南角 | x-、y+ | shore31 |
| 东南角 | x+、y+ | shore07 |

每块均按原始帧0、1、2、3放置；不再使用弯岸的局部窗口或shore41/42的大面积水块作为直岸。沙地带使用green/glat，再过渡到内陆；15种实际使用的GLAT方向已从原像素独立核对，完全连接时使用green实体块。

## 接缝验证

对边界沿同一逻辑方向取12个连续采样段，比较相邻两侧的水面分布。此指标检测水陆轮廓中断；不同原始像素的纹理与泡沫不要求逐字节相同。检查包含模板内部、跨模板、转角、外海和内陆相邻边。

| 当前地图的1,840条岸线相关边 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 平均水陆轮廓差异 | 0.148274 | 0.029906 |
| 最大差异 | 0.941667 | 0.153274 |
| 差异超过0.25的接缝数 | 317 | 0 |

证据和原始边缘数据保存在 [布局数据](../Assets/Generated/Terrain/layout.json)。没有重绘、混色、拉伸或镜像任何原始岸线像素。

[表现隔离及接缝回归](../Tests/PresentationAudit.cs) 检查实际C#地表计划，在四种种子下逐边检查水陆连续性与沙地连接，同时确认世界散列、地形、矿量、建筑占地和导航版本不变。回归还故意恢复旧版错误的shore42南岸块，确认其会被接缝检查拒绝。

[25项核心测试](coast-fix-core-tests.json) 全部通过，包括八人确定性指令流和序列化回放。主工程构建0警告、0错误。[操作回归](coast-fix-ui-regression.json) 通过：240ticks、18接受、0拒绝，录像复算散列仍为`c6e9e1d5f7e48c65`，内容指纹仍为`d1493b9340acc921`。[美术完整性验证](coast-fix-art-integrity.json) 通过，包含15种沙地过渡方向与完整岸线模板校验。

## 原生画面

修复版在现有原生Godot窗口重新运行。选择开局已有坦克，通过鼠标右键命令正常移动至4.5,4.5，由单位视野揭开岸线；没有修改地图或清除黑幕。捕获时tick162，原生Maleoon935帧缓冲2090×1306，显示736个岸线格和720个沙地带格。[运行证据](coast-fix-native/runtime.json)。

## 范围

修复覆盖当前生成地图的矩形海洋边界。额外保留原版凹岸方向，但尚未实现任意地形的对角鞍点（mask6/9）；遇到这类未支持关系会明确报错，不再悄悄放入不相关转角。完整原版高差、悬崖和桥梁不属于本次修复。
